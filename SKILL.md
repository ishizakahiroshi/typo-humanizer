# typo-humanizer

Inject realistic mistakes into a text, the way a person occasionally leaves them. This skill does
**not** rewrite wording, tone, or structure. It only adds the kind of slips a person makes while typing
or dictating. If the user also wants the wording changed, that is a different job (a style humanizer);
do it separately or say so.

People don't make mistakes in every message. A text where every message has a typo reads as careless,
not human. That is why this skill first decides **whether** this text gets any slip at all.

## Inputs

Read these from the user's request. Ask only when the text itself is missing or an explicitly selected pattern conflicts with the requested input mode.

| Input | Default | Notes |
|---|---|---|
| text | — | Pasted text or a file path |
| language | auto-detect | Language name or ISO 639-1 code. A language the user names wins over detection |
| input mode | the pack's default | `keyboard` / `mobile` / `voice`. Packs may define their own modes (e.g. Japanese `flick`). `mixed` when requested or when the user selects patterns from multiple modes |
| pattern(s) | all compatible rows | One or more error IDs or type names from the language pack. Restricts which mechanisms can be used. An explicitly selected pattern forces a slip unless the user also specifies frequency |
| frequency (ゆらぎ度) | `2/10` | Chance this text gets any slip: `N/10`. At `2/10`, about 2 requests in 10 get slips and the rest come back unchanged. "Always" / 「必ず」 means `10/10` |
| intensity | `1` | Density when slips are added, from `1` (fewest) to `10` (most). An explicitly provided intensity forces a slip unless the user also specifies frequency. `light` / `medium` / `heavy` remain aliases for `1` / `4` / `10` |
| exact count | none | A count such as "3 typos" overrides frequency and intensity, forcing exactly that many slips for this text |
| genre | auto-detect | `chat` / `email` / `document`. Changes how many slips survive and which kinds |
| show changes | off | When on, list every change after the text |
| protect | see Step 5 | Extra words or spans the user wants left untouched |

## Step 1: Load the language pack

1. Decide the language. If the text mixes languages, use the dominant one and treat spans in other
   languages as protected, unless a pack for that language also exists.
2. Look for `langs/<code>.md` in the directory that contains this `SKILL.md` (`<code>` is ISO 639-1:
   `ja`, `en`, `vi`, ...). If it exists, read it and follow it.
3. If it does not exist, build a temporary pack from your own knowledge of the language, following the
   structure of `langs/_template.md`: how people type it (keyboard layouts, input methods such as
   Telex/VNI or pinyin), frequent misspellings, diacritic habits, speech-to-text confusions.
   Include only mechanisms you are confident actually occur. Keep the pack in your working context;
   do not write a file. Put this notice, in the user's language, directly before the output:
   > No language pack for <language>. The typos were generated by AI inference and may look unnatural
   > to native speakers. To improve this, add a pack based on `langs/_template.md`.

A pack may add error types, input modes, protected patterns, and its own density table.
A pack cannot relax Step 5 (Protect) or Step 7 (Check).

## Step 2: Pick the input mode

Use the mode the user asked for; otherwise use the pack's default. A selected pattern can determine the mode when the user did not name one. If selected patterns belong to multiple modes, combine them only when the user asks for `mixed` or explicitly selects patterns from those modes. If a selected pattern conflicts with an explicit single mode, explain the conflict and ask which to use.

## Step 3: Decide whether this text gets slips (frequency)

1. An exact count overrides frequency, forces slips, and skips the roll.
2. If the user specified a frequency, use it. `10/10`, "always", or 「必ず」 forces slips. For a lower frequency, roll a whole number from 0 to 9; the text gets slips only if the number is below N (at `2/10`: only on 0 or 1).
   - If you can run shell commands, roll with one of these:
     `node -e "console.log(Math.floor(Math.random()*10))"`,
     `python -c "import random; print(random.randrange(10))"`,
     PowerShell `Get-Random -Maximum 10`, or bash `echo $((RANDOM % 10))`.
   - If you cannot, decide yourself and mark the summary line with `roll: AI judgment`.
     Language models are poor at randomness, so the real rate may drift from N/10.
3. If the user explicitly selected patterns or intensity but did not specify a frequency, force at least one slip and skip the roll.
4. Otherwise use the default `2/10` frequency and roll as above.
5. If the roll says no, skip to Output and return the text unchanged.

## Step 4: Decide how many

1. Take the pack's baseline density at intensity `1` (or the table below if the pack has none). Compute the multiplier as `1 + (intensity - 1) / 3`, then compute the expected number as `text length ÷ baseline density × multiplier`.
2. Adjust it by genre: `chat` × 1.5, `email` × 1, `document` × 0.5. People proofread formal writing
   more, so fewer slips survive there.
3. Choose the actual number near that value, not always exactly it: anything from about half to about
   1.5 times, and at least 1 (this text was already chosen to get slips).
4. An exact count from the user overrides the density and genre calculations.
5. Mistakes already in the text stay as they are and count toward the number.

| Text unit | Baseline density at intensity 1 |
|---|---|
| Characters (CJK and similar) | 1 per 300 |
| Words (space-separated languages) | 1 per 60 |

Intensity rises evenly from the existing `light` density at level `1` to the existing `heavy` density at level `10`. Level `10` targets four times the count at level `1`; `medium` maps to level `4`.

## Step 5: Protect

Never change:

- Numbers, amounts, dates, times, units, percentages, phone numbers, IDs
- URLs, email addresses, file paths, commands, code blocks, inline code, and markup syntax
  (heading markers, list markers, link targets)
- Proper nouns (people, companies, products, places), unless the user opts in
- Quotations and citations
- Negations and any word whose change flips or blurs the meaning
- Safety-critical content: medication and dosage, legal terms, instructions where a misreading can
  cause harm. If most of the text is like this, say so and ask before going ahead
- Anything the user listed

## Step 6: Choose and place slips like a person, not a pattern

- **Mechanisms are fixed, words are free.** Use only the mechanisms (rows) the pack lists. A row's
  examples only illustrate the mechanism: apply it to words that are actually in the text, and do not
  copy the example words.
- **Prefer slips a writer would miss on a quick reread.** Use rows marked `subtle` in the pack's
  Visibility column. Use `noticeable` rows only in `chat` or at intensity `4`–`10`, unless the user
  explicitly selected that pattern.
- If the user selected patterns, use only those rows. Otherwise choose from all rows compatible with
  the input mode, using their weights. Do not silently replace an unknown, inapplicable, or conflicting
  selected pattern with another type.
- If a selected pattern is unknown or has no safe place in the text, explain why and return the original
  unchanged instead of choosing a substitute.
- **Don't space slips evenly.** Real slips gather in long sentences, in the second half of a long
  text, and in long or less common words. Two slips close together are fine, and whole paragraphs
  without any are normal. Greetings and sign-offs, typed many times a day, get fewer slips.
- **Don't repeat a typing slip.** If the same word appears several times, a typing slip hits one
  occurrence, not all of them.
- **Habits are rare.** A row marked `habit` is a spelling belief, not a typing slip. If you use one,
  keep it consistent within the text, but most texts should contain no habit at all.
- **Mix types only when useful.** When no pattern was selected, pick by the pack's weights and don't
  let one row dominate. With selected patterns, stay within that selection.
- Every slip must be recoverable: a reader should know the intended word at a glance.
- Never produce an offensive, vulgar, or embarrassing word, and never produce a word that changes the
  claim (for example "can" becoming "can't").
- Leave everything else exactly as it was: whitespace, line breaks, punctuation, formatting.

## Step 7: Check before output

Compare the result with the original and confirm all of the following. Redo any change that fails.

- The number of changes matches Step 4
- Every protected span is unchanged
- Each change uses a mechanism from the pack, is recoverable, inoffensive, and keeps the meaning
- Read the whole result once as its reader would. It should look like a normal person writing
  quickly, not a careless or ignorant writer. If it looks sloppy, remove the most conspicuous slip
  and read it again

## Output

1. The no-pack notice from Step 1, if it applies
2. The text in a single fenced code block, with nothing else inside it. When the roll said no, this is
   the original text, unchanged
3. One summary line in the user's language. Include the count or intensity, selected pattern when
   present, mode, genre, and roll or forced state. Examples:
   `2 changes · keyboard · intensity 4 · pattern K5 · chat · roll 1 (2/10)`, or
   `No slips this time · keyboard · intensity 1 · roll 7 (2/10)`
4. If show changes is on and there are changes, a table: `# | original | changed | type`

## Don't

- Don't rewrite style, tone, vocabulary, or structure.
- Don't imitate a specific real person's writing habits.
- Don't claim or imply anything about AI-detection tools.
- Don't write files unless the user asks; this skill returns text.
